## 构建

官网 EdgeOne 保持 Node 22.11 和原安装流程。Node 24 开发环境使用：

```sh
npm --prefix games/ship-battle ci --ignore-scripts
npm run game:ship:build
```

这会生成 runtime/（只有 Vite 编译产物）及 runtime-manifest.json。原 public/ 素材只保存一份。官网每次构建检查全部运行源码/依赖锁/公共资源/运行包 SHA-256，拒绝源码与运行包不一致；CI 在 Node 24 重新构建并校验结果。dist 只包含 public 原始资产、许可证及 runtime，排除源码、文档、测试、独立演示页。

接入所需兼容修改仅在 BattleRenderer.ts：引入 Pixi 官方 CSP 静态实现；关闭生成 blob worker，继续使用浏览器异步 ImageBitmap 解码。官网 CSP 没有放宽，不加 unsafe-eval，不修改模拟引擎或节奏。

两张产品预览位于 /assets/game-previews/，由本地实际运行截图生成 WebP，总计约 99KB。选择页打开才设置图片 src，官网首页不预载任何游戏代码或新游戏素材。

## 2026-10-21 加载与长期缓存修复

窗口打开后启动限定在 /games/ship-battle/ 的缓存 worker。按文件 SHA-256 保存游戏代码、配置、224 张原始飞船图、环境和内置头像，共 266 项资源；既有缓存不主动删除，更新只补新 revision。浏览器可授予持久存储，仍不能承诺绕过浏览器自身的空间回收。

本局准备不等全库：先保证当前局资源，后台预下载最多2个、低优先级、不解码或分配GPU贴图；当前局初始化/抽签时暂停预下载，准备完成后继续。关闭窗口中止下载，完成的缓存保留，下次续传。缓存 worker 不控制官网主页，不处理视频/相册。不开根作用域 worker、不新增轮询或服务端调度。

同源成员握手改为在 React 场景和抽舰之前完成，避免先加载内置阵容，再收到官网名单后重新抽舰的一次重复准备。保留原 ready/set-members 协议兼容旧嵌入宿主，开局/伤害/随机分配/舰船像素保持。

两处普通进度条：本局按实际完成的飞船素材计数；选择页显示全库缓存进度。首次提示以实际 CacheStorage 是否为空判断，有部分数据提示补齐，完整缓存后隐藏首次提示；不使用访问次数或 localStorage 首次标记。支持缓存失败时回退正常联网游戏，不阻塞玩家。

已验证全关浏览器/重启后禁用网络仍可启动，缓存后离线三次重新抽签约120–158ms；这不是所有设备/网络的时延保证。源码和构建校验照旧。
