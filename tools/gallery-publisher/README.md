# GVY 相册发布器

这是舰队官网专用的本地相册发布工具。它只监听 `127.0.0.1`，用于选择照片、调整顺序、生成图片、检查预览，并在二次确认后只提交本批相册。

## 使用

1. 在 Finder 中双击仓库根目录的 `GVY相册发布器.app`。它会启动或复用本机服务，确认健康后自动打开浏览器并显示系统通知；启动器自身随后退出，所以以后每次双击都会重新执行，不会出现“后台应用已激活但没有窗口”的假死状态。
2. 拖入或选择 JPG、JPEG、PNG、HEIC、HEIF 照片，单批最多 100 张、单张最多 50 MB。
3. 按需要调整本批照片的先后关系；发布时会按当前顺序直接追加到官网相册末尾。官网和发布器都不显示照片编号。内部资源文件仍使用不可见的唯一 ID，防止复用旧缓存 URL。
4. 点击“生成本地预览”。工具会生成1280 WebP、按原图宽度决定是否生成1920 WebP、640×360缩略图，并运行基础站点门禁、相册工具检查与预览构建；不运行无关视频元数据或游戏长测。
5. 打开官网预览，确认相册顺序与“最新”按钮能到达本批照片。
6. 点击“发布相册”。发布器只提交本批相册文件，建立回滚标签，推送独立分支并创建PR；基础站点门禁和相册相关检查通过后普通合并，再复查两个正式域名。

已有官网照片可通过“选择并删除官网照片”管理。支持单选或多选；生成删除预览前会再次列出数量和文件范围。删除只移除所选照片，其他照片保持当前先后关系；下次新增继续追加到末尾。预览会暂时移出相册条目、原图、WebP 和缩略图，正式发布前点击“清空本批”可完整恢复。

如果 `.app` 无法使用，可双击 `启动GVY相册发布器.command` 作为备用。Codex 对话中的文件链接只能定位或打开文件，不能代替 Finder 双击执行应用。

## 安全边界

- 相册操作、提交和检查范围独立。CI根据准确Git基线与候选读取首页原文，只接受可用原追加/删除操作完整重建的HTML；不能仅因文件名是index.html就忽略其他变化。额外标签、脚本、旧照片元数据或导航变化不享受相册分流；共享/未知文件仍完整检查。
- 当前官网仍是同一个EdgeOne项目，照片提交仍会发布该项目的静态产物；本轮没有新建独立内容部署项目、改DNS或存储。完全独立内容发布是另一层范围，不能把独立工作区/检查称作已经实现独立部署。
- 不保存 GitHub 或 EdgeOne 密钥，直接使用电脑现有的 Git 凭据与仓库部署配置。
- 相册在`.runtime/site-worktree`独立Git工作区处理，以最新`origin/main`和两个正式域名相册为基准。开发工作区的暂存、未暂存、未跟踪文件均不复制、不清理、不提交，不会因为开发日志未提交而阻止上传。
- 独立相册工作区本身出现非本批改动时仍会停止并保留现场。已有预览不能在Git基线或文件内容改变后继续发布/回滚，不能用强制覆盖解决冲突。
- 独立工作区首次或锁文件变化时安装依赖；后续在有效安装和锁文件一致时复用，不每批重新下载。
- 目标文件已存在时停止处理，不覆盖旧照片。
- 新增照片在生成文件前会与正式官网当前相册及同一批照片进行文件和视觉指纹比对；疑似重复时显示对比图，由用户决定是否继续。
- 删除使用隐藏的稳定资源 ID 精准定位文件；ID 不在界面显示，也不参与照片排序。不得重命名现存资源或复用旧资源 URL。
- 正式提交生成前可以“清空本批”，恢复 `index.html` 并删除本批派生文件。
- 正式提交生成后若推送失败，保留提交并允许再次点击发布；不会用强制推送或破坏性重置处理失败。
- 通过普通PR合并后禁止本地回滚；必需检查失败不会合并，提交/PR保留可重试，不绕过保护。线上复查失败会明确提示已合并待复查。
- 修复前的旧预览仍保留在原工作区供安全清空；不会自动搬运、删除或直接推送main。旧批次未提交时请清空后重新生成。

## 开发与验证

```sh
npm run gallery:publisher
npm run gallery:publisher:test
npm run gallery:publisher:build
npm run verify
./script/build_and_run.sh --verify
```

运行时会话保存在忽略提交的 `tools/gallery-publisher/.runtime/`，前端产物保存在同样忽略提交的 `tools/gallery-publisher/dist/`。

macOS 启动入口源码是 `macos-launcher.applescript`，实际应用包为仓库根目录的 `GVY相册发布器.app`；公共启动逻辑位于 `launch-macos.zsh`，脱离启动器继续运行服务的入口是 `run-server-macos.zsh`。`script/build_and_run.sh` 负责停止、重建、签名、启动和验证应用，Codex 的 Run 动作也使用它。启动失败会弹出提示、在 Finder 中定位 `tools/gallery-publisher/.runtime/launcher.log`，便于直接交给 Codex 排查。
