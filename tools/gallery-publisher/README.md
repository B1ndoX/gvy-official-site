# GVY 相册发布器

这是舰队官网专用的本地发布工具。它只监听 `127.0.0.1`，用于选择照片、调整顺序、生成官网图片、检查本地预览，并在二次确认后发布正式网站。

## 使用

1. 在 Finder 中双击仓库根目录的 `GVY相册发布器.app`。它会启动或复用本机服务，确认健康后自动打开浏览器并显示系统通知；启动器自身随后退出，所以以后每次双击都会重新执行，不会出现“后台应用已激活但没有窗口”的假死状态。
2. 拖入或选择 JPG、JPEG、PNG、HEIC、HEIF 照片，单批最多 100 张、单张最多 50 MB。
3. 调整顺序；官网可见编号会从当前最后一张自然续接，第一张显示“本批起点”，供官网“最新”按钮精准定位。内部资源文件使用历史高水位之后的新 ID，不会复用删除过的文件名。
4. 点击“生成本地预览”。工具会生成 1280 WebP、按原图宽度决定是否生成 1920 WebP、640×360 缩略图，并运行官网完整验证。
5. 打开官网预览，确认相册顺序与“最新”按钮的精准落点。
6. 工作区干净且位于 `main` 时，可进入正式发布确认。发布器只提交本批文件，建立发布前回滚标签，推送后等待 EdgeOne，并复查两个正式域名。

已有官网照片可通过“选择并删除官网照片”管理。支持单选或多选；生成删除预览前会再次列出数量、可见编号和文件范围。删除后官网可见序号自动连续补位，现存图片文件不会改名。预览会暂时移出相册条目、原图、WebP 和缩略图，正式发布前点击“清空本批”可完整恢复。

如果 `.app` 无法使用，可双击 `启动GVY相册发布器.command` 作为备用。Codex 对话中的文件链接只能定位或打开文件，不能代替 Finder 双击执行应用。

## 安全边界

- 不保存 GitHub 或 EdgeOne 密钥，直接使用电脑现有的 Git 凭据与仓库部署配置。
- 生成预览前已有本地改动时，允许预览但锁定正式发布。
- 目标文件已存在时停止处理，不覆盖旧照片。
- 新增照片在生成文件前会与官网现有照片及同一批照片进行视觉指纹比对，重复内容会被拒绝。
- 删除使用隐藏的稳定资源 ID 精准定位文件；界面只显示连续的相册位置号。不得通过重命名现存资源来补可见序号。
- 正式提交生成前可以“清空本批”，恢复 `index.html` 并删除本批派生文件。
- 正式提交生成后若推送失败，保留提交并允许再次点击发布；不会用强制推送或破坏性重置处理失败。
- main 推送成功后即禁止本地回滚；线上复查失败会明确提示“代码已推送”。

## 开发与验证

```sh
npm run gallery:publisher
npm run gallery:publisher:test
npm run gallery:publisher:build
npm run verify
./script/build_and_run.sh --verify
```

运行时会话保存在忽略提交的 `tools/gallery-publisher/.runtime/`，前端产物保存在同样忽略提交的 `tools/gallery-publisher/dist/`。

macOS 启动入口源码是 `macos-launcher.applescript`，实际应用包为仓库根目录的 `GVY相册发布器.app`；公共启动逻辑位于 `launch-macos.zsh`，脱离启动器继续运行服务的入口是 `run-server-macos.zsh`。`script/build_and_run.sh` 负责停止、重建、签名、启动和验证应用，Codex 的 Run 动作也使用它。启动失败会弹出提示、在 Finder 中定位 `tools/gallery-publisher/.runtime/launcher.log`，便于直接交给 Codex 排查。
